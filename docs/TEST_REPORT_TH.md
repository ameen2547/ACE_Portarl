# รายงานทดสอบ ACE Content Portal

วันที่: 2 พฤศจิกายน 2026

ขอบเขต: User Mapping, report-style UI, error `NetworkError ... HTTP -1` บนมือถือ, การเชื่อมรายงาน `Gift_Details`, การแบ่งหน้าฝั่งเซิร์ฟเวอร์ และการยืนยัน Admin ก่อนดูรหัสผ่าน VJ

## ผลทดสอบซอร์ส

รันทดสอบด้วย `npm test` โดยจำลองบริการ Apps Script และข้อมูลชีตตัวอย่างในเครื่อง

- ผ่าน 20 รายการ
- ไม่ผ่าน 0 รายการ
- ทดสอบการ parse JavaScript ในหน้าเว็บ, การแสดงองค์ประกอบ report ของ VJ/Admin, การกรองข้อมูล VJ, สิทธิ์ Admin, การแบ่งหน้าประวัติ, marker snapshot รายวัน, ตัวจัดการเชื่อมต่อฝั่งหน้าเว็บ, การจับคู่ Gift ด้วย TikTok ID และการจำกัดแถว Gift ตาม VJ
- ทดสอบ User Mapping report ส่งครั้งละ 50 รายการพร้อมสรุปยอดจากผลลัพธ์ทั้งหมด, history-only อ่านเป็นช่วงจากท้ายชีต, การค้นหาแถว Snapshot ของวันปัจจุบันจากท้ายชีต และการเปิดรหัสผ่านด้วย PIN Admin ที่ตรวจสอบฝั่งเซิร์ฟเวอร์

## การปรับหน้า User Mapping

ปรับโครงให้ใช้แนวทางหน้า Report เช่น แถบตัวกรอง, ปุ่มเลือกช่วงวันที่ลัด, การ์ดสรุป, ภาพรวมข้อมูลตามทีม และแท็บรายการปัจจุบัน/ประวัติ แสดงผลบนมือถือด้วยตารางเลื่อนแนวนอนและการ์ดสรุป 2 คอลัมน์ ใช้ชื่อฟิลด์และข้อมูล User Mapping เดิม ไม่เปลี่ยน Schema

## ปัญหาที่พบและการแก้ไข

1. **โหลดประวัติทั้งหมดในคำตอบเดียว** ทำให้ response และจำนวนการ์ดที่หน้าเว็บสร้างโตตามข้อมูลสะสม และอาจล้มเหลวบนมือถือด้วย `HTTP -1`  
   **แก้แล้ว:** โหลดครั้งละ 100 รายการล่าสุด มีปุ่มโหลดประวัติเก่ากว่า และคงให้เรียกดูประวัติชุดเดิมได้ครบ

2. **VJ ประมวลผลข้อมูลทุกคนก่อนกรองชื่อของตน** และมีการขอ avatar cache ให้ประวัติทั้งหมด  
   **แก้แล้ว:** กรองฝั่งเซิร์ฟเวอร์ก่อนสร้างผลลัพธ์ และโหลด avatar cache เฉพาะข้อมูลปัจจุบัน

3. **การอ่าน User Mapping ทำงาน snapshot พร้อมล็อกทุกครั้ง** และอ่านประวัติซ้ำในคำขอเดียว  
   **แก้แล้ว:** ส่งข้อมูลประวัติที่อ่านแล้วเข้า routine snapshot, ใช้ล็อกแบบไม่รอคิวนาน และใช้ Script Properties ระบุวันที่ snapshot เพื่อลดการสแกนซ้ำ ในกรณีต้องสร้าง Snapshot สำรองจะอ่านเฉพาะช่วงท้ายของวันที่ปัจจุบันก่อนหยุดที่วันที่เก่ากว่า

4. **การเรียงประวัติหักล้างลำดับล่าสุดก่อน**  
   **พบจากการทดสอบ:** รายการของวันเดียวกันถูกเรียงตามชื่อ ทำให้แถวแรกไม่ใช่รายการใหม่สุด  
   **แก้แล้ว:** รักษาลำดับ snapshot ล่าสุดก่อน ส่วน UI ยังจัดกลุ่มตามวันที่ ทีม VJ และบุคคล

5. **เมื่อคำขอเครือข่ายล้มเหลว ไม่มี retry และไม่มี guard ตรวจ `google.script.run` ในตัวโหลด User Mapping**  
   **แก้แล้ว:** ตรวจ bridge ก่อนเรียก, retry หนึ่งครั้งเฉพาะ error เครือข่ายชั่วคราว และปิดสถานะกำลังโหลดเมื่อ retry ไม่สำเร็จ

6. **ข้อมูล Gift_Details ยังไม่เชื่อมกับรายชื่อและทีมใน User Mapping**
   **แก้แล้ว:** เพิ่มแท็บรายงานของขวัญทั้งฝั่ง VJ และ Admin อ่านข้อมูลจากแท็บ `Gift_Details` ในไฟล์ฐาน User Mapping จับคู่ TikTok ID โดยรองรับ ID ที่มีหรือไม่มี `@`, แสดงสรุปเหรียญ/รายการ/ผู้ส่ง/ยอดตามบุคคลที่จับคู่ได้ และแบ่งผลลัพธ์ครั้งละ 50 แถวพร้อมตัวกรองวันที่ ทีม และคำค้น เพิ่มรูปโปรไฟล์จาก User Mapping และรูปของขวัญจาก JSON ของ BeetGames ที่จับคู่ด้วยชื่อ พร้อมภาพสำรองกรณีไม่พบรูปหรือโหลดไม่ได้

7. **ข้อมูลของขวัญมีรายละเอียดผู้ส่ง จึงต้องกรองก่อนส่งให้หน้าเว็บ**
   **แก้แล้ว:** API ตรวจ Session ก่อนอ่านข้อมูล จำกัด VJ ให้เห็นเฉพาะแถวที่ VJ ตรงกับบัญชีที่ล็อกอิน (หรือแถวไม่มีค่า VJ แต่ User Mapping ระบุผู้รับผิดชอบตรงกัน) และซ่อนรายละเอียด mapping หาก TikTok ID ถูกมอบหมายให้ VJ คนอื่น ส่วน Admin เห็นข้อมูลทั้งหมด API อ่านอย่างเดียวและไม่แก้ Schema A–J

8. **ตาราง User Mapping ปัจจุบันมีรายการจำนวนมากในหน้าเดียว**
   **แก้แล้ว:** ตารางฝั่ง VJ และ Admin ขอข้อมูลจากเซิร์ฟเวอร์ครั้งละ 50 รายการ มีปุ่มก่อนหน้า/ถัดไปและกลับไปหน้าแรกเมื่อเปลี่ยนตัวกรอง ส่วนการ์ดสรุปและภาพรวมทีมคำนวณจากข้อมูลที่ตรงกับตัวกรองบนเซิร์ฟเวอร์ ประวัติจะเริ่มโหลดเมื่อเปิดแท็บ และอ่านจากท้ายชีตครั้งละช่วงจนได้ 100 รายการที่ตรงกับผู้ใช้ ประวัติเก่าจะอ่านเมื่อกดปุ่มเพิ่ม

9. **การค้นหาและดูรายละเอียด VJ ยังอาศัยรายการทั้งหมดในหน่วยความจำของเบราว์เซอร์**
   **แก้แล้ว:** หน่วงการค้นหา 250 มิลลิวินาทีเพื่อลดคำขอซ้ำ, เปิดรายละเอียด VJ ด้วยคำขอเจาะจง VJ และแบ่งหน้า 50 รายการ, ส่วน CSV จะขอข้อมูลเป็นชุดละ 500 รายการเฉพาะเมื่อกดส่งออก

10. **หน้า Admin มีข้อมูลรายชื่อ แต่การเปิดรหัสผ่านไม่มีการยืนยันซ้ำ**
    **แก้แล้ว:** หน้าเว็บไม่โหลดรหัสผ่านล่วงหน้า การดูแต่ละครั้งต้องส่ง PIN ของ Admin ที่กำลังเข้าสู่ระบบไปตรวจบนเซิร์ฟเวอร์ก่อนคืนรหัสของ VJ ที่เลือก จำกัดความพยายาม, บันทึกผลตรวจโดยไม่บันทึก PIN หรือรหัสผ่าน และซ่อนค่าที่เปิดภายใน 30 วินาทีหรือเมื่อออกจากแท็บ

## ข้อจำกัดของการทดสอบ

การทดสอบรอบนี้ใช้ mock ในเครื่อง จึงยืนยันการกรอง การแบ่งหน้า การยืนยัน PIN และรูปแบบหน้าเว็บจากโค้ดได้ แต่ยังไม่ได้เปิดหน้า `/dev` เพื่อตรวจข้อมูลสดใน Google Sheets จริง การเข้าถึงขึ้นกับสิทธิ์ Spreadsheet ของบัญชีที่รัน Apps Script และการเปลี่ยนแปลงนี้ยังไม่ได้อัปโหลดไป Apps Script deployment
